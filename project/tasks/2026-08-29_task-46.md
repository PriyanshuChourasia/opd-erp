# Task 46 — Appointment edit history

Date: 2026-08-29
Status: Completed

## Task Given

Prompt 1 — Appointment edit history:
Appointment has no history tracking today (confirmed: no AppointmentHistory model exists), unlike Prescription, which already has this exact pattern via PrescriptionHistory (schema.prisma:682-700: prescriptionId, version, snapshot fields, items as a JSON snapshot, changeType/changeReason, createdAt/createdById, cascade-linked to the parent). Mirror it: add an AppointmentHistory model (appointmentId, version, a previousData Json snapshot of the appointment's fields before the edit, changeType/changeReason, createdAt/createdById, onDelete: Cascade from Appointment). In appointments.service.ts's update method, before applying changes, write the current row's state into AppointmentHistory (versioned, incrementing), then update Appointment in place — same as however prescriptions.service.ts already does this for prescriptions (mirror its exact approach, don't reinvent it).

Follow-up verification: Edit an appointment (change date/doctor/fee/etc.) twice. Confirm two AppointmentHistory rows exist afterward, each holding the state before that particular edit, versions incrementing correctly, and the live Appointment row shows the latest (current) values. Confirm deleting an appointment cascades its history (or decide/flag if history should survive deletion instead — that's a call worth surfacing, not assuming). Redo if any snapshot is off-by-one or missing.
