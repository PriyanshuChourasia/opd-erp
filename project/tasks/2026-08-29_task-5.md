## Task Accomplished

- **JWT in the Laravel admin-api (minimal `users` table).** Installed `tymon/jwt-auth` v2.3.0 (supports Laravel 13 / PHP 8.5) + Laravel Boost (dev). Published `config/jwt.php`, generated `JWT_SECRET` into `.env`, added `JWT_*` vars to `.env.example`. Added a stateless `jwt` guard backed by the `users` provider in `config/auth.php`, and made `App\Models\User` implement `JWTSubject` (`getJWTIdentifier` / `getJWTCustomClaims`).
- **Reworked `Modules/Auth` to issue real JWTs against the `users` table** (replacing the Sanctum + `admins` flow): `POST /api/auth/login` → `{ accessToken, tokenType, expiresIn, user }`; `GET /api/auth/me`, `POST /api/auth/refresh`, `POST /api/auth/logout` (stateless logout blacklists the token), all behind `auth:jwt`. Fixed a pre-existing PSR-4 bug by moving `LoginRequest` to `Modules/Auth/Http/Requests/`. Sanctum/`admins` left in place but out of the auth path.
- **Demo user + credentials in UI.** Seeded `admin@opderp.com` / `Password@123` (plus `test@example.com` / `password`) via `DatabaseSeeder` (`updateOrCreate`), and show them in the admin-ui login page and dashboard.
- **Connected admin-ui to admin-api.** Discovered admin-ui's Vite proxy pointed at `:4003`, which is actually the doctor-erp NestJS API — repointed it to `:8100` for the Laravel API. Wired auth in the UI: `loginApi`/`logoutApi`, session restore via `GET /auth/me` (`useMe`), `useLogout` mutation calling the API, `hasToken()` guard, route guard + redirect on `/` and new `/dashboard`, and 401 interceptor now redirects to `/` (was stale `/login`). New protected dashboard shows the JWT-verified profile, endpoint status, and demo credentials.
- **Verified end-to-end over HTTP** (API direct and through the admin-ui Vite proxy): login (JWT `sub=2`, user `Head Admin`) → `me` 200 → `refresh` OK → `logout` 200 ("Logged out successfully.") → `me` 401. Bad credentials → 401. `tsc --noEmit`, `vite build` (dashboard route code-split), and ESLint all pass.
