### Two PDF flows exist on the appointments page:

---

### Flow 1: Per-Appointment Slip PDF (Download PDF button in dialog)

**Complete trace:**

1. **PDF button UI** — `appointments-page.tsx:1353` — `<Button disabled={generatingPdf} onClick={downloadPrintPdf}>Download PDF</Button>` inside a `<Dialog>` (line 1217)
2. **Dialog trigger** — `appointments-page.tsx:171` — `const [printAppt, setPrintAppt] = useState<Appointment | null>(null)` — dialog opens when `printAppt` is non-null
3. **Click handler** — `appointments-page.tsx:175-203` — `downloadPrintPdf()` uses `html2pdf.js` to render `printPreviewRef.current` div to a PDF blob, creates a temporary `<a>` element, sets `href` to a blob URL, and calls `.click()` to trigger download
4. **No backend endpoint** — PDF is generated entirely client-side via `html2pdf.js` (no API call)
5. **Response/download handling** — Blob URL created, `<a>.click()` triggers browser download, URL revoked after 10 seconds

**🔴 ROOT CAUSE: The dialog can never be opened.**

`setPrintAppt()` is **never called with an appointment value** anywhere in the file. The only calls are:
- `setPrintAppt(null)` — in `onOpenChange` (line 1217) to close the dialog
- `setPrintAppt(null)` — in the Close button (line 1348)

**There is no Printer icon button in the table's actions column** (lines 546-617) that would call `setPrintAppt(appt)` to open the dialog. The actions column has:
- Eye button → navigate to edit page
- HeartPulse button → open vitals
- ClipboardList button → create prescription (COMPLETED only)
- FileText button → generate invoice (COMPLETED + unpaid only)
- Status Select → change status

**The entire downloadPrintPdf() function and the slip preview dialog are unreachable dead code.**

### Flow 2: Bulk Appointments Report PDF (top-level "PDF" button)

**Complete trace:**

1. **PDF button UI** — `appointments-page.tsx:712-715` — `<Button variant="outline" size="sm" onClick={exportToPdf} disabled={!appointments.length}>PDF</Button>`
2. **Click handler** — `appointments-page.tsx:238-285` — `exportToPdf()` builds an HTML table string from appointment data, creates a temporary `<div>` element, appends it to `document.body`, uses `html2pdf.js` to convert to PDF, then removes the element
3. **No backend endpoint** — PDF is generated entirely client-side
4. **Response/download handling** — `html2pdf().from(element).save()` triggers browser download directly

**🟡 Potential issue:** This flow appears functional but has a minor fragility — the dynamically created DOM element may not render properly for html2canvas in some browsers since it's appended directly to `document.body` without being mounted in the React tree. However, this is a less critical flow.

### Summary

The root cause is simple: **the Printer button that should open the slip preview dialog was never added to the table actions column**. The dialog, the `downloadPrintPdf()` function, the `browserPrint()` function, and the `printPreviewRef` are all fully implemented but unreachable because no UI element calls `setPrintAppt(appt)`. The fix is a single button addition (~5 lines of JSX) plus importing the `Printer` icon.
