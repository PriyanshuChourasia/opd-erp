# TASK 100-101 — Outstanding Payment Query & API

## Summary

Implemented the backend service method and API endpoint for the Outstanding / Pending Payment Report.

## Backend Changes

### 1. Service Method (`apps/api/src/reports/reports.service.ts`)

Added `getOutstandingPayments()` method that:

- **Filters by date range**: Defaults to last 90 days
- **Default filter**: Only PENDING or PARTIAL bills (excludes fully paid)
- **Supports filters**:
  - `doctorId` — filter by doctor (via appointment relation)
  - `patientId` — filter by patient
  - `paymentStatus` — override default filter
  - `from/to` — date range
  - `page/limit` — pagination

- **Returns per row**:
  - Patient info (name, phone)
  - Appointment info (date, id)
  - Doctor info (name, specialization) — resolved via `getDoctorNameMap` (polymorphic User link)
  - Invoice info (number, total, paid, pending)
  - Payment info (method, reference, status)

- **Summary includes**:
  - Total records, billed/paid/pending amounts
  - Aging buckets (0-30, 31-60, 61-90, 90+ days)
  - By status breakdown

### 2. Controller Endpoint (`apps/api/src/reports/reports.controller.ts`)

```
GET /api/reports/outstanding-payments
  ?from=YYYY-MM-DD
  &to=YYYY-MM-DD
  &doctorId=uuid
  &patientId=uuid
  &paymentStatus=PENDING|PARTIAL|PAID|CANCELLED|REFUNDED
  &page=1
  &limit=50
```

### 3. Doctor Name Resolution

Doctor names are resolved via `getDoctorNameMap()` from `common/utils/doctor-names.ts` — this handles the polymorphic `User.userableType='Doctor'` / `userableId=doctorId` link, since the Doctor model has no direct firstName/lastName fields.
