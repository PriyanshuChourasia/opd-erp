# Task 19 — Connect Amount input to fee data

**Status:** Complete
**Date:** 2026-08-30

## Task Given

Connect the new Amount input in the Fee Summary to the appointment fee state/model.

Requirements:
- User can enter an amount
- Amount must be numeric
- Existing fee calculations must remain functional
- Prevent invalid negative values
- Keep the input synchronized with the appointment form state

## Task Accomplished

### Existing connections (already wired before this task)

The Consultation Fee and Registration Fee inputs were already connected to `form.amount` and `form.registrationFee` respectively from prior tasks (TASK 16, 17, 18). The full chain was already functional:

```
Input onChange → setForm({ amount: ... }) → form.amount →
  ├─ Total: form.amount + regFeeAmount
  ├─ Book button: "Book · {currency(form.amount + regFeeAmount)}"
  ├─ createMutation: amount: form.amount
  └─ bookAndPayMutation: amount: form.amount
```

### What was added/fixed

| Change | Why |
|--------|-----|
| `Math.max(0, ...)` on Consultation Fee onChange (new-appointment-page.tsx) | `Number(e.target.value) \|\| 0` handles NaN but not negative values. `min={0}` only affects browser stepper buttons, not manual typing. |
| `Math.max(0, ...)` on Registration Fee onChange (new-appointment-page.tsx) | Same reason — prevents negative registration fees. |
| `Math.max(0, ...)` on Consultation Fee onChange (edit-appointment-page.tsx) | Consistency — edit page had the same gap. |
| `Math.max(0, ...)` on Registration Fee onChange (edit-appointment-page.tsx) | Same consistency fix. |

### Validation trace

| Check | Status |
|-------|--------|
| User can enter amount | ✅ Input accepts numeric values |
| Amount is numeric | ✅ `type="number"` + `Number()` |
| Existing fee calculations work | ✅ Total, Book button, mutations all use `form.amount + regFeeAmount` |
| Negative values prevented | ✅ `Math.max(0, ...)` clamps at 0 |
