# Task 20 — Inspect existing booking flow

**Status:** Complete

## Task Given

## Task Accomplished — Investigation Report

### 1. UI Buttons (new-appointment-page.tsx)

Two action buttons at the bottom of the form:

| Button | Label | Behavior | Disabled when |
|--------|-------|----------|---------------|
| **Book** | `Book · ₹{amount + regFee}` | `createMutation.mutate()` — creates appointment, navigates back | `!canBook` or either mutation pending |
| **Book & Pay** | `Book & Pay ₹{amount + regFee}` | `setPaymentSheetOpen(true)` — opens PaymentSheet | `!canBook` or either mutation pending |

`canBook = !!form.patient && !!form.doctorId && !!form.slot && !!form.type`

Both buttons show the **total amount** (`form.amount + regFeeAmount`) inline.

### 2. Book Button Flow (createMutation)

```
User clicks "Book"
  → createMutation.mutate()
    → updatePatient (if allergies changed)
    → POST /appointments (createAppointment)
      → body: { patientId, doctorId, date, type, amount, registrationFee?, notes? }
    → on success: invalidate queries → toast "Appointment booked successfully" → navigate back
```

**No payment/invoice is created.** The appointment is created unpaid.

### 3. Book & Pay Flow (bookAndPayMutation)

```
User clicks "Book & Pay" → PaymentSheet opens
  → User selects payment method (CASH/CARD/UPI/CHEQUE/OTHER)
  → User optionally enters discount, tax, notes
  → User clicks "Confirm & Book"
    → createMutation.mutate()
      → POST /appointments (same as above)
    → checkoutAppointment(appointment.id, { paymentMethod, discount, tax, notes })
      → POST /appointments/:id/checkout
        → body: { paymentMethod, discount, tax, notes }
    → on success: invalidate queries (appointments, doctor-slots, billing) → toast "Appointment booked and paid successfully" → navigate back
```

### 4. Backend — Appointment Creation (appointments.service.ts)

**Endpoint:** `POST /appointments` → `create(dto, userId)`

```
1. Generate tokenNumber from date + patient name
2. Determine registrationFee:
   - If provided in DTO → use it
   - If not provided → auto-assign company default for first-time patients, 0 for returning
3. Create Appointment record with: patientId, doctorId, date, type, amount, registrationFee, tokenNumber, notes
4. Create AppointmentHistory v1 (CREATE) snapshot
5. Return appointment (with patient, doctor, bill included)
```

**Key:** Appointment is created with status `SCHEDULED`. **No bill is created during booking.**

### 5. Backend — Checkout (appointments.service.ts)

**Endpoint:** `POST /appointments/:id/checkout` → `checkout(id, dto)`

```
1. Find appointment (with patient + bill)
2. Validate: appointment must exist, must not already have a bill
3. Generate invoiceNo (INV-YYMM-XXXXX)
4. Calculate: subtotal = consultationAmount + registrationAmount
5. total = subtotal - discount + tax
6. Create Bill record with:
   - patientId, appointmentId, invoiceNo
   - subtotal, discount, tax, total
   - paymentMethod, notes
   - BillItems:
     - CONSULTATION item (unitPrice = appointment.amount)
     - REGISTRATION item (if registrationFee > 0)
7. Return bill with items + patient
```

**Key:** The checkout reads `appointment.amount` and `appointment.registrationFee` directly from the Appointment record — it does NOT use the amounts from the PaymentSheet. The PaymentSheet only sends `paymentMethod`, `discount`, `tax`, `notes`.

### 6. Invoice Preview (from appointment list)

**Endpoint:** `GET /appointments/:id/invoice-preview`

Returns a draft invoice:
```json
{
  "appointment": { ... },
  "alreadyInvoiced": false,
  "items": [
    { "itemType": "CONSULTATION", "itemName": "WALK_IN — John Doe", "quantity": 1, "unitPrice": 500 },
    { "itemType": "REGISTRATION", "itemName": "Registration Fee — John Doe", "quantity": 1, "unitPrice": 100 }
  ]
}
```

This is used by the appointments list page's "Generate Invoice" button (on unpaid rows). It opens an Invoice Preview sheet where the user can adjust discount/tax/payment before confirming.

### 7. Payment Status Handling

| Where | How payment status is tracked |
|-------|-------------------------------|
| **Appointment model** | No `paymentStatus` field — payment status is inferred from `bill` relation |
| **Bill model** | `status` defaults to `"PENDING"`, `paymentMethod` defaults to `"CASH"` |
| **Appointments list UI** | `appt.bill ? <Badge>Paid</Badge> : <Badge>Unpaid</Badge>` — boolean check |
| **After checkout** | Bill is created → `appt.bill` becomes truthy → shows "Paid" badge |

### 8. Amount/Money Displayed on Book Actions

| Location | What's shown |
|----------|-------------|
| Book button text | `Book · ₹{amount + regFee}` (total) |
| Book & Pay button badge | `₹{amount + regFee}` (total) |
| PaymentSheet subtotal | `{amount + regFee}` as Subtotal |
| PaymentSheet net total | `subtotal - discount + tax` |
| Invoice preview items | Consultation fee + Registration fee as line items |

```
Form State                    Backend                    Display
──────────                    ───────                    ───────
form.amount ──────────────→ Appointment.amount ──────→ Invoice item (unitPrice)

form.registrationFee ────→ Appointment.registrationFee → Invoice item (unitPrice)

PaymentSheet.tax ─────────→ Bill.tax
PaymentSheet.method ──────→ Bill.paymentMethod
```
