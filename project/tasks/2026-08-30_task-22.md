# Task 22 — Implement Book payment status

**Status:** Already Implemented (No changes needed)
**Date:** 2026-08-30

## Task Given

Update the Book flow on /appointments/new. When user selects only Book:
- Create the appointment
- Do not initiate payment
- Set payment status to Pending
- Do not generate an invoice

## Task Accomplished

The Book-only flow **already works correctly** through the existing bill-based payment tracking system.

### How It Works

| Flow | What happens | Payment status |
|------|-------------|----------------|
| **Book only** | `createMutation` → `createAppointment()` only | **Pending** (no bill exists) |
| **Book & Pay** | `bookAndPayMutation` → `createAppointment()` + `checkoutAppointment()` | **Paid** (bill exists) |

### Verification

1. **Book-only flow** (`createMutation` in `new-appointment-page.tsx:311-329`):
   - Calls `createAppointment()` with: patientId, doctorId, date, type, amount, registrationFee, notes
   - Does NOT call `checkoutAppointment()` — no bill generated
   - No payment initiated

2. **Backend create** (`appointments.service.ts:66-113`):
   - Creates Appointment record with status `SCHEDULED`
   - Creates AppointmentHistory v1 (CREATE)
   - Does NOT create any Bill record

3. **Payment status display** (`appointments-page.tsx:580-602`):
   - `appt.bill ? <Badge>Paid</Badge> : <Badge>Unpaid</Badge>`
   - Book-only appointments have `bill = null` → shows "Unpaid" (Pending) badge ✓

4. **No invoice generated for Book-only**:
   - `checkout()` in `appointments.service.ts:434-480` is never called
   - No `Bill` or `BillItem` records created

### No Changes Required

The existing bill-based system already provides explicit payment status tracking:
- **Pending** = no bill exists (`appt.bill` is `null`)
- **Paid** = bill exists (`appt.bill` is truthy)
