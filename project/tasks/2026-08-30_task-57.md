# Task 57 — Prevent editing existing vitals

**Status:** Already Implemented (Read-only by design)
**Date:** 2026-08-30

## Task Given

Remove/disable editing of existing Patient Vitals records.

## Verification

### Backend

- No `@Patch` or `@Put` endpoint on patient-vitals controller
- No `@Delete` endpoint on patient-vitals controller
- No `update()` or `remove()` method in service
- Only create + read operations exist

### Frontend

- No edit button on vitals display (new-appointment-page.tsx:806-831)
- Vitals shown as read-only text fields (label + value)
- No `updatePatientVitals` or `deletePatientVitals` API functions
- "Add" button only opens create form, not edit form

### Behavior

| Action | Status |
|--------|--------|
| View existing vitals | ✅ Read-only display |
| Create new vitals | ✅ "Add" button + Sheet form |
| Edit existing vitals | ❌ Not possible (no endpoint, no UI) |
| Delete existing vitals | ❌ Not possible (no endpoint, no UI) |

### No Changes Needed

The vitals system was designed as immutable (write-once, read-many). No edit/delete functionality exists to remove.
